Get started

Chronicle documentation

Chronicle turns recordings of your screen and system events into agent harnesses. A harness holds context files, workflows, and a knowledge graph of your work.

Quickstart

Load a sample workday and open the app. Chronicle records nothing.

Build a harness

Combine context files, workflows, and a graph for one line of work.

Connect an agent

Give Claude, Cursor, ChatGPT, and other clients access over MCP.

Chronicle has three levels, from general to specific:

LevelWhat it isExample
HarnessEverything an agent needs for a whole line of workRecruiting
Context fileGeneral guidance for one kind of session, like an agent fileResearching job companies
WorkflowA short procedure for one specific job, like a skillCustomizing resume bullets to keep their formatting and length

The screens and GIFs on this page show a synthetic sample workday and no real screen data. The GIFs omit the time spent waiting on a model.

Quickstart

Quickstart loads a synthetic workday, so Chronicle records nothing. You need uv.

  1. Install Chronicle. 
    uv tool install --python 3.12 "chronicle-context[graph]"
  2. Load the sample workday. 
    chronicle demo
  3. Start the app. 
    chronicle serve
  4. Open http://127.0.0.1:3030.

The app opens on Knowledge, and the list of recordings shows Sample workday.

To print what an agent receives, run this command in another terminal:

chronicle context "finish the Acme export"
# Computer context (Chronicle)
Task: finish the Acme export
Window: the most recent 2h of history.

## What you were doing
- 14:55-15:31 meeting Acme weekly · Jordan Hale (36m)
- 15:34-16:24 writing customer emails · export spec (50m)
- 16:28-16:48 coding export.ts · asking Priya (20m)

## On screen now
- Chrome · Checks · PR 882 (frame 18)
- URL: https://github.com/northwind/billing/actions

Next, set up a model so that Chronicle can write context files and workflows. Then build a harness.

Your first recording

Check what this computer can capture:

chronicle doctor
platform: darwin
[ok] front window: Cursor
[ok] idle time: 0.23
[ok] clipboard: readable
[ok] screenshot: 451 KB
[ok] OCR: tesseract
[!!] accessibility: grant Accessibility to the app that runs Chronicle

On macOS, Chronicle needs Screen Recording and Accessibility. The permission belongs to the app that runs Chronicle. That app is your terminal for chronicle record and chronicle serve. If an agent starts the recording, that app is the host, such as Claude Desktop or Cursor. Each browser also shows one Automation prompt before Chronicle can read its URLs.

  1. Open System Settings › Privacy & Security.
  2. Add the app that runs Chronicle to Screen & System Audio Recording and Accessibility.
  3. Quit that app completely, then reopen it. Closing its windows isn't enough.
  4. On Knowledge, choose a duration.
  5. Type what you're about to do.
  6. Press Start recording. The panel shows live storage, frames, system events, pages, apps, and graph nodes.
  7. Press Stop and build graph, or let the timer finish.

To record from the terminal, run these commands. An agent can also record with start_recording.

chronicle record 30m --label "file an expense report"
chronicle stop
chronicle sessions

A duration is between 10 seconds and 7 days, written as 90s, 15m, or 1h30m. Press Ctrl-C to stop early. chronicle record captures in its own terminal. --detach only starts the session, so a running chronicle serve must do the capturing.

The mini window in the sidebar keeps a record button and a timer above your other windows. It needs a browser that supports Document Picture-in-Picture.

Ontology

Knowledge

Knowledge is the app's first page. The top of the page shows the knowledge graph of all your history, with a chat beside it. The chat answers from the graph and its evidence, cites frames, and highlights the nodes it names. Without a model, the chat answers from search.

The chat can also start work. Type a request such as "build a harness for my billing work". With a model set up, the chat proposes a harness, context file, or workflow, and names its sources. Chronicle builds nothing until you press the button on the proposal, so text captured in a recording can't start a build. The buttons under the chat open the full forms.

Below the chat, the page shows the controls for a new recording and the list of your recordings.

Groups

Related nodes form groups, and each group's name stays on screen when it fits. A model names the groups when one is set up. Otherwise, Chronicle uses automatic names. Press a name to rename it. To move a node, double-click it, keep holding, and drag it onto another group, or use the node's panel. Names and moves apply to every graph and stay after a rebuild.

Change the legend

Every graph has a legend. The legend starts with People, Apps, Websites, Files, and Other. Press a row to highlight that category. Edit legend has these controls:

  • Rename, add, or remove a category.
  • Choose a color from the palette or a color wheel.
  • Choose which kinds of node belong to each category.

To change one node, select it, then rename it or move it to another category. These changes apply to every graph in the app and to what agents read over MCP. They stay after a rebuild.

Expand a graph

The expand button at the top right of a graph fills the window, with the chat on the right. Scroll to zoom. To go back, press Esc or the X at the top of the chat.

Chat history

Chronicle saves a chat when you send it, and your latest chat returns after a reload. History reopens or deletes an earlier chat, and New chat starts another. Each recording keeps its own history. Chronicle stores chats only in your Chronicle folder.

Recordings

A recording is the source of everything else. Every 5 seconds by default, Chronicle samples the front app, its window, and the browser URL (macOS). When something changes, and at least every 30 seconds, Chronicle also takes a screenshot and reads screen text from the Accessibility tree or OCR. Without Screen Recording, Chronicle takes no screenshots. Chronicle logs these system events: app_switch, window_focus, url_change, clipboard, idle_start, idle_end, session_start, and session_stop.

Chronicle never records keystrokes and skips password managers and System Settings. Chronicle redacts emails, API keys, JWTs, and card numbers before it writes anything.

When a recording ends, Chronicle builds its graph. If a model is set up, the model then refines the graph and writes context files and workflows in the background. If no model is set up, Chronicle stops after the graph.

A recording has five tabs:

TabWhat's there
Knowledge graphThe graph, a node inspector, habitual app switches, and a chat about this recording
Contexts and workflowsWhat Chronicle generated from this recording, and buttons to make more
TimelineActivity by app, frames with screenshots, system events, tasks, and URLs
MeetingsTranscripts, decisions, and action items that a speech-to-text tool sends to POST /add
SearchGraph nodes, screen text, transcripts, events, URLs, and context files

All history, at the bottom of the recordings list, combines every recording. Older recordings count less.

Knowledge graph

Each recording gets its own graph, with nodes for:

  • Apps, windows, sites, pages, and search queries
  • Topics, files, tickets, PRs, and code identifiers
  • People, projects, customers, meetings, and tasks

Every node and edge records its time and its source frames, so an agent can cite its evidence.

Drag to rotate, and pinch to zoom. Select a node to list what you did there, with its system events and frames. Windows, identifiers, and other low-level kinds stay hidden until you choose Show everything or filter by kind. With Refine with model, a model names the real work, merges duplicates, and adds typed relations.

Ask about a recording

The chat beneath a recording's graph answers from that recording only. The answer cites frames that you can open. Without a model, the chat falls back to a search of the recording.

Graph commands

chronicle graph show --session 1
chronicle graph find acme
chronicle graph node pr:882
chronicle graph tasks --session 1
chronicle graph tune --session 1
chronicle ask "Where did we land on the Acme export columns?"
chronicle search invoice_id

graph tune needs a model, and fails with no model is set up without one. Without a model, ask returns search results instead of a written answer.

Context files

A context file is general guidance for one kind of session, like an agent file. A context file says where things stand, how to work, and what to reference. A procedure belongs in a workflow instead. Use one context file alone for a small session, such as backtesting or making a presentation. Combine more than one in a harness.

Generate context files

If a model is set up, it writes context files when a recording ends. For older recordings, open Contexts and workflows and press Generate from this recording. The model reads everything recorded and names up to four files for the sessions it finds, such as "Researching job companies". Without a model, Chronicle builds a General file and up to two other files from the evidence, based on the recording's keywords.

To write a file for specific work, press New on the Contexts page or New context file on a recording. With a model, the form suggests complete options from your knowledge graph. Press an option to fill in every field, or type a name and press Fill in the rest from what I've typed. Without a model, the form suggests only names and recordings. The form has these fields:

  • Name and Description of the work: what the session is and what an agent must know before it starts.
  • Recordings to look at: one or more, combined into one file.
  • Earlier contexts to look at: if a recording disagrees with an earlier context, the file follows the recording.
  • Workflows to use: the file names each workflow and says when to use it, without a copy of its steps.

Choose at least one source. Without a source, Chronicle refuses the request. Without a model, or if the model fails, Chronicle builds the file directly from the sources.

Sections of a context file

A model-written file has these sections. The model omits a section if the evidence doesn't support it.

  • Where things stand: what you were doing and where you left off.
  • How to work here: instructions from what you did, such as which tools to use and what to check first.
  • Sections for that kind of work: tickets and PRs for coding, or sources read for research.
  • Reference: exact files, URLs, identifiers, and people.
  • Open threads: what's unfinished.

Each file also has a small graph of the nodes it uses, and a list of the workflows made from it or its recording. Download .md includes both, so one file works as a single upload.

Workflows

A workflow is a short, action-oriented procedure for one specific job, like a skill. A workflow has these parts:

  • A trigger
  • Inputs, written as {placeholders}
  • Three to seven steps
  • What to confirm first
  • A small graph

Chronicle marks a step Confirm first if it sends, submits, publishes, pays, merges, or deletes.

Press New on the Workflows page, or Make a workflow on a recording or context file. The form suggests options in the same way as the context file form, and has these fields:

  • Name and What it's for request one specific workflow. If both are blank, the model finds up to five workflows in your sources.
  • Recordings to scan and Context files to scan set what it reads, so one workflow can use more than one recording.

A workflow must cite frames from your sources, and Chronicle rejects a workflow that cites other frames. If the model can't find the work in your sources, the app tells you and writes nothing. Workflows need a model that supports tool calls.

Downloads use the same frontmatter as skills (name and description), so you can copy a file directly into a skills folder.

Harnesses

A harness is everything an agent needs for a whole line of work. A harness holds:

  • AGENTS.md: what the harness is for, which file to load when, and rules that hold everywhere.
  • contexts/: context files.
  • workflows/: workflows.
  • graph/: a graph engine that merges the recordings you choose, including their system events.

Build one

On Harnesses, press New harness, or press Build a harness on a recording. The wizard has five steps:

  1. Purpose: enter a general name and a detailed description, or choose an option under the name. With a model, the options come from the tasks and topics in your knowledge graph. Then choose which AI tools can use the harness. Tools found on your computer start ticked.

    Build writes to each ticked tool's config file and keeps a backup. A connected tool can read all your harnesses, not only this one. To reverse the change, disconnect the tool on Integrations.

  2. Recordings: choose what its graph is built from.
  3. Contexts: choose existing files. With a model, Chronicle marks the files that fit your description as Suggested. A model can write files here for a recording that has none.
  4. Workflows: choose existing workflows, and list any to write. The model proposes what's missing, and you can edit that list.
  5. Review: check the file tree, then build.

Chronicle copies files into the harness, so an edit there never changes the originals. If the recordings can't support a workflow you requested, the app names that workflow and builds the rest.

Edit one

A harness opens in an editor with three panes:

  • Left: the file tree. Use + to add a file, and Export to download.
  • Middle: tabs for open files, with Preview and Source. Save with ⌘S.
  • Right: a chat that reads every file. The chat can edit, add, or remove files, or write a new workflow from the recordings. Each change appears as a chip that you can open.

Undo reverses the last change from the chat or from a save. Review each chat change, because a model can soften or misread a request. A chat edit fails if the model's text doesn't match the file. The chat then reports the failure and changes nothing. Chat edits need a model that supports tool calls. Source works without a model.

The graph engine

graph/engine in the file tree shows the merged graph. From there, you can search its nodes and system events, and change its recordings.

Guides

Privacy & Sources

Privacy & Sources sets what Chronicle reads besides your recordings. Every source starts off, except Screen, which runs only during a recording. A source that you turn on syncs every 10 minutes. Its items join your all-history graph and the Knowledge chat. Harnesses and recordings keep their own graphs.

Forget deletes everything a source read, and has no undo.

Retention also applies to source items. At the default of 30 days, Chronicle keeps only items from the last 30 days, even if the source holds more.

Set up a model

A model that you choose writes contexts, workflows, and harnesses.

  1. Open Settings › Model.
  2. Open a provider.
  3. Add its key.
  4. Press Test. Chronicle sends one small request.
  5. Press Use.

Each provider keeps its own key and model, so you can switch at any time.

A key can also be in a .env file in ~/.chronicle or the current directory. Your choice in Settings overrides CHRONICLE_LLM. The exception is CHRONICLE_LLM=off, which turns models off whatever Settings says.

Use a local model

Chronicle works with any OpenAI-compatible endpoint, including Ollama and LM Studio. These steps use Ollama, which must be running.

  1. Pull a model. 
    ollama pull llama3.2
  2. Open Local model in Settings. The endpoint defaults to http://localhost:11434/v1, and your pulled models appear under Model.
  3. Choose a model.
  4. Press Test.
  5. Press Use.

Chat about a recording works with any model. Workflows, harness chat, and context file names use tool calls, so choose a model that supports them. A model without tool support gets the tools described in the prompt instead, and small models often fail at this. In our November 2026 testing, gemma3:4b answered questions well but couldn't write a valid workflow or edit a file.

Data sent to the provider

The active provider receives window titles, URLs, system events, and redacted screen text. A local model keeps this data on your computer. With no model, Chronicle runs offline. It still records, builds graphs, searches, and builds plain context files.

Tool order for agents

An agent calls list_harnesses first. If a harness fits, the agent uses these tools:

  1. get_harness reads AGENTS.md.
  2. read_harness_file loads the files that AGENTS.md names.
  3. search_harness_graph looks up nodes and system events.

get_context adds what's on screen now. A local server starts a recording when an agent calls start_recording. Only one Chronicle process captures at a time.

Hosted agents and APIs

Hosted agents and APIs run on another company's servers, so they need a public HTTPS URL. chronicle serve exposes MCP at /mcp. Set a token, then put the server behind a tunnel that you control.

Anyone with the URL that these commands print can read your Chronicle data.

export CHRONICLE_TOKEN=$(openssl rand -hex 16)
export CHRONICLE_PUBLIC_URL=https://YOUR-TUNNEL-HOST
chronicle serve &
cloudflared tunnel --url http://127.0.0.1:3030
echo "$CHRONICLE_PUBLIC_URL/mcp/$CHRONICLE_TOKEN"

Stop the tunnel when you finish. If the URL leaks, change the token. A client that supports headers can use /mcp with Authorization: Bearer instead. A request with no token or a wrong token gets a 401.

ChatGPT:

  1. Open Settings › Connectors › Advanced.
  2. Turn on Developer mode.
  3. Create a connector with the URL and no authentication.

The search and fetch tools return the format that connectors and deep research expect.

APIs: chronicle mcp config prints a starting point for each API. Provider model names and beta flags change often, so check each provider's MCP documentation.

chronicle mcp config openai-api
chronicle mcp config anthropic-api
chronicle mcp config gemini-api
chronicle mcp config http

The examples folder has longer scripts.

MCP server

Two transports share one set of tools: stdio with chronicle mcp, and Streamable HTTP at POST /mcp on a running server. GET /mcp returns 405. The server supports protocol versions 2025-06-18, 2025-03-26, and 2024-11-05. To inspect the server:

npx @modelcontextprotocol/inspector --cli chronicle mcp --method tools/list

Resources and prompts

Resources: chronicle://context/current, chronicle://graph/summary, and chronicle://sessions. Templates: chronicle://harness/{id}, chronicle://context-file/{id}, chronicle://workflow/{id}, chronicle://context/session/{session_id}, and chronicle://frame/{frame_id}.

Your data

Chronicle keeps everything in ~/.chronicle: db.sqlite, screenshots in media/, and capture.lock. Chronicle has no account and no telemetry. Data leaves that folder only through agents you connect and the model you choose.

A delete is permanent, and Chronicle has no undo for it. Deleting a recording removes its frames, events, graph, and context files. Harnesses and workflows keep their own text.

To delete a recording, press Delete on the Knowledge page. To delete everything, delete the folder. Delete a harness or workflow separately to remove its text. The full policy is in PRIVACY.md.

Troubleshooting

You seeWhat to do
[!!] accessibility from chronicle doctorGrant Accessibility to the app that runs Chronicle, then quit and reopen that app. Until then, screen text comes from OCR if tesseract is installed
[!!] front window from chronicle doctor on LinuxChronicle needs X11, a window manager, and xdotool. Wayland sessions aren't supported. Until this check passes, recordings have 0 frames
A recording with 0 framesA process must capture. chronicle record captures in its own terminal, and --detach needs a running chronicle serve. Make sure that CHRONICLE_DISABLE_CAPTURE isn't set
no model is set upAdd a model. Make sure that CHRONICLE_LLM isn't off
duration must be between 10 seconds and 7 daysUse a duration in that range, such as 30s
History is not empty from chronicle demoThe sample loads only into an empty database. --force permanently deletes your history. To keep your history, set CHRONICLE_HOME to another folder
Your model does not support tools, or workflows fail on a local modelUse a local model with tool support, or a cloud provider
Screenshots are off: Screen Recording isn't grantedAdd the app that runs Chronicle to Screen & System Audio Recording, then quit and reopen that app. Closing its windows isn't enough
needs Full Disk AccessAdd the app that runs Chronicle to Full Disk Access, then quit and reopen that app
401 from the APICHRONICLE_TOKEN is set. Send it as Authorization: Bearer
An agent doesn't see ChronicleRestart the client, then inspect its MCP list. chronicle mcp config prints the expected entry
