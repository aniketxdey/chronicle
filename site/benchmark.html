Benchmark

This benchmark tests whether a computer-use agent completes more tasks when it can draw on a knowledge graph of its own earlier work than the same model without it, and whether the graph matters or just having history does.

Method

Benchmarks

BenchmarkWhy
OSWorld 2.0108 long workflows in Ubuntu VMs with self-hosted services. 43 of them are tagged implicit-state inference: the agent has to recover state the instruction doesn't give it, which is the problem Chronicle is built for.
OSWorld-Verified360 shorter desktop tasks in test_nogdrive.json, each from a fresh VM. Chronicle has no user history here, so any gain has to come from experience across tasks. This is the harder test for Chronicle.

How the pilot builds the graph

The protocol follows the online setting of Agent Workflow Memory. Each task runs once per arm, in waves of 4 and in the same shuffled order. After each wave, the harness ingests that arm's recordings and rebuilds its graph. Each task can only draw on earlier waves.

  • The harness excludes evaluator results, reference solutions, and human demonstrations of test tasks.
  • The recorder captures successful and failed runs. It excludes agent actions and reasoning.
  • All three arms use the same recorder. Injected context counts toward each arm's token cost.

Arms

ArmAgent got
Raw modelThe benchmark's standard observation and action space
Plain memoryThe recorded frames that best match the task, ranked by BM25 over the same recordings
ChronicleThe get_context pack for the task: knowledge graph, timeline, and cited evidence

Both memory arms receive the same preamble and the same 8,000-character budget, which the harness adds to the instruction at the start of each task. The plain-memory arm separates the value of the graph from the value of having any history at all. The full protocol is in bench/PROTOCOL.md.

Retrieval Test

This ran through the same ingestion and context code as the OSWorld arms, with no agent and no VM. It asks whether the text that answers a question reaches the agent at all. It measures retrieval on conversational datasets, not whether an agent completes more tasks, and Chronicle's graph was built without a model.

Plain search still found more evidence than Chronicle's context pack, by 19.9 points on LoCoMo and 14.9 on LongMemEval. The pack beat simply handing over the newest frames by 40.0 and 71.6 points. It carries 6 evidence passages next to its graph, while search spends the whole budget on up to 40.

What changed the pack's score

The first run scored the pack at 2.7% on LoCoMo and 14.5% on LongMemEval. Its evidence came from a search ordered by time: a full question rarely matches on every word, so the search fell back to any word and returned the 6 newest hits. Evidence is now ranked by relevance and cut to the matching passage, which produced the numbers above. The graph section names topics but doesn't carry the passages this metric looks for, so a pack can be useful in ways recall doesn't measure.

How to read this

  • Metric. A turn counts as found when 6 consecutive words of it appear in the output, or all of it if shorter. A passage that was paraphrased or cut off counts as missed. Recall is the share of a question's evidence turns found.
  • Fit. These datasets are conversations replayed as one turn per frame, not screen recordings, and Chronicle's graph is built for screens and system events. Treat this as a check on what gets retrieved, not as a memory-system leaderboard entry: no answers were generated or graded.
  • Latency. Measured on an arm64 laptop with Python 3.14 and 6 worker processes running at once, so it's an upper bound on an idle machine.

Harness Robustness

These confirm the pilot's code path works. They produce no scores.

  • Planning ran for both benchmarks: 108 OSWorld 2.0 tasks at osworld-v2.1 with 43 implicit-state, sampled to 20 tasks in 5 waves; 360 OSWorld-Verified tasks across 10 domains, sampled to 60 in 15 waves.
  • Real OSWorld-Verified instructions with synthetic screen text went through ingestion and context building 112 times. None went over budget and none came back empty.
  • Canaries planted in fields that ingestion should ignore, and 260 evaluator strings from the task files, never appeared in any context. This covers the ingestion path, not a live VM run.

Reproduce

The retrieval and graph numbers were measured on 4 November 2026 with the code in the commit that added them to this page, and need no accounts apart from an OpenAI key for the graph quality run.

uv venv && uv pip install -e ".[graph,llm]" && source .venv/bin/activate
mkdir -p bench/runs/datasets/longmemeval && cd bench/runs/datasets
git clone --depth 1 https://github.com/xlang-ai/OSWorld
git clone --depth 1 --branch osworld-v2.1 https://github.com/xlang-ai/OSWorld-V2
git clone --depth 1 https://github.com/snap-research/locomo
curl -L -o longmemeval/longmemeval_s https://huggingface.co/datasets/xiaowu0162/longmemeval/resolve/main/longmemeval_s
cd ../../..
python bench/retrieval.py --data bench/runs/datasets --out bench/runs/retrieval --lme 470 --workers 6
PYTHONPATH=. python scripts/bench_graph.py
PYTHONPATH=. python scripts/eval_graph.py
